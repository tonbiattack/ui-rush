# UI Rush 仕様書（MVP）

## 1. 目的
UIコンポーネント・インタラクションの**見た目、動き、名称、読み方**を短時間で覚えるWebクイズ。AIへの音声指示で正確なUI用語を即座に言えることを目指す。

## 2. 体験の原則
- **1問数秒**で直感的に回答できる。画面遷移や長い説明を挟まない。
- 静止画だけではなく、**実際に操作できるデモ**を出題する。
- スマホを優先し、PCでは数字キー1〜4でも回答できる。
- クイズは匿名・ログイン不要、データベース不要で開始できる。

## 3. MVPの画面
1. **ホーム**：スタート、制限時間（3/5/8秒、既定5秒）、出題数（10/20問、既定10問）、正誤表示後の進め方（自分で次へ／自動で5秒後）、モードの選択。
2. **クイズ**：上部に進捗と残り秒数（数字＋プログレスバー）、中央に操作可能なUIデモ、下部に4択ボタン。正誤表示中はタイマー停止と「次へ」ボタンを表示。
3. **結果**：正答数・正答率・時間切れ数・間違えた用語一覧、再挑戦と間違い復習。

## 4. 出題ルール
- 問題形式は**「このUIは何という？」** の4択。1問につき正解1つ。
- デモを自由にタップ・クリックして挙動を確かめられる。操作していてもタイマーは停止しない。
- 各問の制限時間は開始時からカウントダウン。既定5秒。3/5/8秒から選択可。
- **0秒になったら時間切れ＝不正解**。解答・時間切れ後は**タイマーを停止**し、正答と短い説明を表示したまま待機する。ユーザーが「次へ」を押すと次の問題へ進み、その時点から制限時間を計り直す。
- テンポを優先したい人向けに「自動で次へ（5秒後）」も選べる。既定は「自分で次へ」。
- 回答は最初の1回だけ受け付ける。二重タップ、タイマーと回答の競合で二重集計しない。
- 問題順はセッションごとにシャッフル。同じセッションでは重複させない。
- 選択肢は同系統のUI名称から生成・シャッフルし、正解が固定位置にならないようにする。
- 途中終了時は成績を確定せずホームへ戻れる。
- 正誤は選択確定後に初めて表示し、出題中に答えが漏れないようにする。

## 5. 問題データ
用語**50種類**とキーボード操作**10問**を収録する（`QUESTIONS` / `KEYBOARD_QUESTIONS`）。すべてに操作できるデモを用意する。
各項目に `id`, `kind`, `nameJa`, `nameEn`, `reading`, `aliases`, `description`, `exampleInstruction`, `reversePrompt`, `demoType`, `category` を持たせる。
- `aliases` は別名・表記ゆれ。検索と音声回答の照合にだけ使い、問題としては出題しない。
- `reversePrompt` は逆引きの出題文。名称・英語名・別名を含めない。
- `exampleInstruction` は「AIへの指示にそのまま使える一文」とし、正誤表示と用語図鑑で提示する。
- 名称の重複・別名（例：トースト/スナックバー）は問題文・解説で区別できる場合だけ出題し、紛らわしい4択を避ける。
- `kind: "keyboard"` の用語は通常の4択に混ぜず、キーボード操作モードだけで出題する。選択肢も同じ種類から作る。

## 5.1 呼び分け特訓
- 紛らわしいペア（トースト/スナックバー、セレクト/コンボボックス、ポップオーバー/ツールチップ、ドロワー/ボトムシート、スライダー/プログレスバー、タブ/タブバー、バッジ/チップ、アラート/バナー、プログレスバー/プログレスリング、スピナー/プログレスバー等）を両方向で2択出題する。
- 選択肢は「正解＋紛らわしい相手」だけにし、名称の違いに集中できるようにする。
- 1セッション内で同じ用語を二重に出題しない。
- 正誤表示では両方の名称・説明・「呼び分けのコツ」を並べて比較する。

## 6. 保存と復習
- `localStorage` に問題別の正解数・不正解数・時間切れ数を保持。
- **苦手復習**では不正解または時間切れの問題だけから出題。対象がなければ案内を表示。
- **今日の復習**（間隔反復）では、正誤と最終回答日時から次回復習日を決める。正解は連続回数に応じて1→3→7→14→30→60日と伸ばし、誤答・時間切れは翌日に戻す。期限が来た用語だけを出題する。
- 履歴の削除をホーム/設定から可能にする。
- タイムアタックの自己ベストは別キーで保存する（サーバー不要）。

## 6.1 追加モード
- **逆引き**: 自然言語の要件文（名称を含めない）から名称を4択で回答。正解が漏れないことをテストで検証する。
- **キーボード操作**: Tab / Shift+Tab / Enter / Space / Esc / 矢印 / Home / End / Ctrl+K を4択で回答。選択肢もキーの用語だけで構成する。
- **UIパーツ探し**: 模擬画面に並べた模式図から、指定された部品を直接押して回答。誤タップは不正解として1問1結果で記録し、解説時に正解をハイライトする。
- **60秒タイムアタック**: セッション全体が60秒。回答ごとに短く正誤を見せて次へ進む。問題を使い切ったら先頭に戻る。正解数・平均回答時間・自己ベストを表示する。
- **音声回答**: 対応ブラウザでは名称を発話して回答できる。読み・英語名・別名の表記ゆれを吸収し、同義語どうしは一致させない。

## 7. アクセシビリティ/UX
- スマホ縦画面（幅320px程度〜）でデモと回答がスクロールしすぎず使える構成。
- キーボード1〜4で回答、押した選択肢と正解・不正解を明示。
- アニメーション低減設定（prefers-reduced-motion）に配慮。読み上げ可能なラベルをつける。
- 色だけで正誤を表現しない。
- クイズの速度が負担な人向けに、時間制限なしで学べる用語図鑑（`/terms`）を用意する。分類ごとに用語を並べ、デモをその場で操作できる。

## 8. 技術方針
- Next.js（App Router）+ TypeScript + Tailwind CSS。UIデモはReactコンポーネントで実装。
- 問題データは静的TypeScript/JSON。MVPでバックエンド・DB・認証・外部AI APIは不要。
- タイマーは `performance.now()` など実時間に基づいて管理し、バックグラウンド復帰時にも残時間を正しく再計算する。
- 判定・進行・結果集計は純粋関数または明確な状態遷移でテスト可能にする。

## 9. 受け入れ条件
- ホームから10問または20問のクイズを開始できる。
- 3/5/8秒の設定が全問題に反映される。5秒が既定値。
- デモを操作でき、回答しても時間切れでも正誤と解説を表示してタイマーが止まる。
- 「次へ」で次の問題に進み、次の問題は満額の制限時間から始まる（自動送り設定では5秒後に進む）。
- 回答と時間切れが同時でも1問1結果として集計される。
- セッション終了時に結果が表示され、苦手問題を再挑戦できる。
- 用語50種類＋キーボード10問が登録され、すべてのデモを操作できる。
- 全用語にAIへの指示例があり、解説表示と用語図鑑で読める。
- 逆引きの出題文に名称が含まれず、正解が一意である（テストで検証）。
- キーボード操作モードでは、出題も選択肢もキーの用語だけで構成される。
- 呼び分け特訓を開始でき、両方向の2択が重複なく出題される。
- UIパーツ探しで模擬画面の部品を押して回答でき、正解が解説時に強調される。
- 60秒タイムアタックが60秒で確実に終了し、自己ベストが保存・表示される。
- 今日の復習は期限が来た用語だけを出題し、正解で次回期限が先に延びる。
- 用語と別名（`/dictionary`）で別名からも検索でき、呼び分けを10組以上確認できる。
- 音声回答は対応ブラウザで動作し、非対応でも4択で完走できる。
- 用語図鑑で各用語のデモを開いて操作できる。
- スマホ・PCブラウザで動作する。

## 10. 将来拡張（MVP対象外）
- 読み方の音声再生、カテゴリ別出題の絞り込み、連続正解演出、PWA対応。
